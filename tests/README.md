# Тестирование LinguaTrack

Основной набор тестов проекта находится в каталоге `tests/` и запускается через pytest и pytest-django.

## Структура

```text
tests/
├── conftest.py       # Общие pytest-фикстуры
├── test_models.py    # Тесты моделей User, Card, Schedule и BotLog
├── test_sm2.py       # Тесты алгоритма интервального повторения SM-2
└── utils.py          # Вспомогательные функции для тестов
```

На момент фиксации baseline suite содержит 42 теста. Все существующие функциональные тесты проходят.

## Запуск

Установите зависимости проекта и запускайте команды из корня репозитория.

Полный штатный запуск с coverage:

```bash
pytest
```

Функциональный запуск без параметров `addopts` из `pytest.ini` и без coverage gate:

```bash
pytest -o addopts='' tests
```

Запуск отдельных групп:

```bash
pytest -o addopts='' tests/test_models.py
pytest -o addopts='' tests/test_sm2.py
pytest -o addopts='' -m models tests
pytest -o addopts='' -m sm2 tests
```

Имена тестовых файлов должны соответствовать `test_*.py`, классов — `Test*`, функций и методов — `test_*`. Для тестов с доступом к Django DB используйте `@pytest.mark.django_db`. Доступные маркеры зарегистрированы в `pytest.ini`.

## Coverage baseline

`pytest.ini` формирует HTML-отчёт в `htmlcov/`, выводит пропущенные строки в терминал и сохраняет существующий порог `--cov-fail-under=80`.

Текущий общий baseline coverage составляет около 29.13%. Порог 80% пока ожидаемо не выполняется. Поэтому штатный `pytest` после успешного прохождения всех 42 функциональных тестов завершается ненулевым кодом только из-за coverage gate. Это известное состояние baseline, а не функциональное падение тестов.

Порог нельзя снижать или удалять без отдельного решения. Новые изменения должны сопровождаться целевыми regression-тестами и не ухудшать фактическое покрытие затронутого кода.
